# Mini NPU Simulator

Python의 중첩 반복문을 활용하여 NPU(Neural Processing Unit)의 핵심 연산인 MAC(Multiply-Accumulate)을 모의 구현한 프로그램입니다.

## 1. 개발 환경

- Python 3.8 이상 (개발 및 검증 환경: Python 3.12.10)
- Windows PowerShell 및 Visual Studio Code
- Python 표준 라이브러리 사용 (외부 패키지 설치 불필요)

## 2. 주요 기능

**사용자 입력 모드 (3×3)**

필터 A와 필터 B, 입력 패턴을 각각 3×3 행렬로 입력받습니다. 같은 위치의 원소를 곱한 값을 누적하여 MAC 점수를 계산하고, 높은 점수를 얻은 필터를 판정 결과로 출력합니다. 숫자가 아닌 값이나 잘못된 열 개수를 입력하면 오류를 안내하고 재입력을 요청합니다.

**JSON 분석 모드 (5×5, 13×13, 25×25)**

제공된 `data.json`에서 필터와 입력 패턴을 읽어 MAC 점수를 계산합니다. `+`와 `cross`는 `Cross`로, `x`와 `X`는 `X`로 정규화합니다. 계산된 판정과 기대 라벨을 비교해 PASS 또는 FAIL로 기록하며, 데이터 오류가 발생한 케이스는 실패 사유를 출력합니다.

**성능 측정**

`time.perf_counter()`를 사용하여 MAC 연산을 10회 반복 측정하고 평균 시간을 밀리초(ms) 단위로 출력합니다. 성능 분석 대상은 3×3, 5×5, 13×13, 25×25이며 연산 횟수는 각각 9, 25, 169, 625회입니다.

## 3. 실행 방법

프로젝트 루트에서 다음 명령어를 실행합니다.

`python main.py`

실행 메뉴에서 `1`을 선택하면 3×3 사용자 입력 모드가 실행됩니다. `2`를 선택하면 프로젝트 루트의 `data.json`을 분석합니다. `0`을 선택하면 프로그램이 종료됩니다.

3×3 입력 시 행마다 숫자 3개를 공백으로 구분하여 입력합니다. 예를 들어 `0 1 0`과 같은 형식을 사용합니다.

## 4. 파일 구성

- `main.py`: 프로그램 실행 메뉴 및 모드 선택
- `data.json`: 제공된 필터와 검증용 패턴 데이터
- `src/matrix.py`: 행렬 생성 및 크기 확인
- `src/mac.py`: 중첩 반복문을 이용한 MAC 연산
- `src/judge.py`: 라벨 정규화 및 epsilon 기반 판정
- `src/perf.py`: 평균 연산 시간 측정
- `src/mode_input.py`: 3×3 사용자 입력 처리
- `src/mode_json.py`: JSON 로드, 케이스 검증 및 결과 분석
- `src/__init__.py`: Python 패키지 인식용 파일

## 6. 결과 리포트 — 실패 원인 및 성능 분석

1. 본 프로젝트는 Python의 중첩 `for`문을 사용하여 행렬의 각 위치에서 곱셈과 누적 덧셈을 수행하는 MAC 연산을 구현했습니다.
2. JSON 분석에서는 전체 6개 입력 패턴 중 3개가 기대 라벨과 일치했고, 나머지 3개는 `UNDECIDED`로 판정되었습니다.
3. `size_5_1`은 Cross 점수가 0.9, X 점수가 0.8999999999999999로 거의 같아 epsilon 동점 판정이 발생했습니다.
4. `size_13_2`는 Cross 점수가 7.499999999999997, X 점수가 7.5로 매우 근접해 `UNDECIDED`가 출력되었습니다.
5. `size_25_1` 역시 Cross 점수 4.9와 X 점수 4.899999999999999 사이의 차이가 매우 작아 동점 처리되었습니다.
6. 세 실패 사례는 프로그램 오류로 계산이 중단된 것이 아니라, 두 점수의 차이가 판정 기준인 `1e-9` 미만이어서 발생한 결과입니다.
7. 부동소수점 연산에서는 십진수를 이진수로 정확하게 표현하지 못하는 경우가 있어 미세한 수치 차이가 나타날 수 있습니다.
8. 따라서 단순히 두 점수의 대소만 비교하는 대신 epsilon을 적용하여 수치적으로 구분하기 어려운 경우를 별도로 처리했습니다.
9. 기대 라벨이 `+`나 `cross`로 표시되더라도 동일한 `Cross`로 정규화하고, `x`와 `X`도 동일하게 처리해 표기 차이가 오답의 원인이 되지 않도록 했습니다.
10. 잘못된 배열 크기, 유효하지 않은 라벨, 숫자가 아닌 값에 대한 별도 테스트를 수행했으며, 세 경우 모두 오류가 감지되는 것을 확인했습니다.
11. 행렬의 모든 원소를 한 번씩 방문하므로 MAC 연산의 시간 복잡도는 원소 개수에 비례하는 O(N²)입니다.
12. 실제 측정에서도 13×13과 25×25 연산 시간이 작은 행렬보다 길게 나타났지만, 3×3과 5×5의 순서는 반대로 측정되어 짧은 실행 시간에서의 오차와 고정 오버헤드 영향을 확인할 수 있었습니다.
13. 성능 측정은 파일 읽기와 화면 출력을 제외하고 MAC 함수 호출 시간만 측정하여 연산 자체의 수행 시간을 비교하도록 구성했습니다.
14. 이번 구현은 실제 하드웨어 NPU의 병렬 처리 속도를 재현하는 것이 아니라, AI 연산의 기본 원리와 행렬 크기에 따른 계산량 증가를 이해하기 위한 순차 실행 시뮬레이터입니다.

## 7. 결론

MAC 연산, 필터 비교, 라벨 정규화, 부동소수점 오차 처리 및 성능 분석을 하나의 프로그램으로 구현했습니다. 제공된 JSON 데이터의 예상 판정 결과를 재현했으며, 정상 입력과 주요 오류 입력에 대한 검증도 수행했습니다.
